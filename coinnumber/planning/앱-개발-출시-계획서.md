# 과금계산기 개발 및 Google Play 출시 계획서

## 1. 목표와 첫 출시 범위

사용자가 목표 캐릭터의 1회 획득 확률, 1회 뽑기 비용, 확정 천장을 입력하면 누적 획득 확률과 예상 비용을 확인하는 도구를 만든다. 가칭은 ‘과금계산기’다. 게임 재화나 아이템을 판매하는 앱이 아니라 사용자가 직접 입력한 수치를 계산하는 앱이다.

첫 버전은 한국어, 원화, 오프라인 계산, 기기 내부 기록 저장으로 한정한다. 로그인·서버·광고·인앱결제는 다음 단계로 미룬다. 확률은 매회 일정하고, 첫 획득 시 중단하며, 천장 진행도 0회에서 시작하는 모델이다. 확률 상승형 천장, 픽업 실패 후 확정, 이월 천장, 여러 캐릭터 수집, 여러 패키지 조합 최적화는 후속 기능으로 둔다. 다회차 묶음 가격 입력과 1회 단가 환산은 첫 버전에 포함한다.

최신 요청에 따라 시작 → 선택한 방식의 입력 → 결과로 이동한다. 입력 화면은 1회·다회차 두 종류이며 시안에는 총 4개 화면을 보여준다. 최신 시안은 app-screen-concept-v4.png다. 시안은 실제 실행 화면이 아닌 디자인 제안이며 이전 안은 이력으로 보관한다.

## 2. 화면 구성

앱 이름은 **과금계산기**다. 시작 1개, 입력 2개, 공통 결과 1개로 총 4종이며 하단 탭은 두지 않는다.

| 화면 | 구성 | 동작 |
|---|---|---|
| ① 시작 | 앱 이름, 짧은 소개, ‘1회 비용 계산’ 및 ‘다회차 비용 계산’ 버튼, 기록·도움말 링크 | 선택한 방식의 입력 화면으로 이동. 기록·도움말은 보조 시트 |
| ② 1회 입력 | 확률 % · 1회 비용 원 · 천장 회를 가로 한 줄에 배치, 확정 천장 체크박스, 결과 보기 | 입력 검증 후 공통 결과 화면으로 이동 |
| ③ 다회차 입력 | 첫 줄 확률 % · 천장 회, 둘째 줄 묶음 횟수 · 묶음 가격, 1회 환산 비용, 확정 천장 체크박스, 결과 보기 | 예: 10회에 33,000원 → 1회 3,300원으로 환산 후 결과 화면 이동 |
| ④ 결과 | 계산 방식, 최대 비용·횟수, 평균 비용, 천장 미적용 99% 비용, 음식 순환 버튼 하나, 선택한 음식 사진·수량·단가, 다시 계산 | 음식 버튼을 누르면 다음 음식으로 전환. 뒤로가기·다시 계산은 기존 값과 방식을 유지한 해당 입력 화면으로 이동 |

- 천장 체크박스를 끄면 천장 없음으로 계산하고 천장 칸을 비활성화한다. 켜면 유효한 천장 횟수가 필수다.
- 1회 입력은 기존처럼 숫자 입력칸 세 개를 가로 한 줄로 유지한다. 다회차 입력은 네 입력칸을 두 줄로 나누고 ‘10회에 33,000원’처럼 입력하기 쉽게 단위를 고정한다. 확률과 천장은 묶음 단위가 아닌 개별 뽑기 1회 단위다.
- 다회차 화면에 ‘1회 환산 비용 3,300원’과 ‘횟수당 환산 기준으로 계산해요’를 표시한다. 계산 기준은 아래 다회차 비용 원칙을 따른다.
- 결과는 계산 시점의 입력값과 일치해야 한다. 입력 수정 후 ‘결과 보기’를 누르면 다시 계산한다. 기록에 입력 방식, 묶음 횟수·가격도 저장한다.
- 상세 횟수와 확률 설명은 결과 화면의 펼치기, 기록과 도움말은 보조 시트로 제공한다.
- 음식 선택 컨트롤은 **버튼 하나**다. 초기 표시는 ‘치킨 ↻’, 보조 문구는 ‘눌러서 음식 바꾸기 · 1/5’다. 누를 때마다 **치킨 → 족발 → 냉면 → 순대국밥 → 햄버거 → 치킨** 순서로 순환한다. 별도 음식 버튼 목록이나 좌우 버튼은 만들지 않는다.
- 선택한 음식 하나의 사진·이름·수량·단가와 버튼 이름·현재 순번을 동시에 바꾸고 비용 결과는 유지한다. 접근성 이름에 현재 음식과 다음 음식 전환 동작을 알린다.
- 음식 사진은 예시이며 시안에서는 치킨만 표시한다. 실제 구현에는 다섯 음식 사진과 대체 설명을 준비한다.

전체 배경은 흰색, 글자는 검정·짙은 회색, 구분선은 연한 회색으로 한다. 파란 결과 카드와 그라데이션은 사용하지 않는다. 주요 버튼은 짙은 회색, 보조 버튼은 흰색 테두리형으로 한다. 작은 화면, 키보드 표시, 큰 글꼴에서는 세로 스크롤을 허용한다.

### 다회차 비용 원칙

- 묶음 횟수 k는 1 이상의 정수, 묶음 가격 B는 0 이상의 정수 원이다. 빈값·0회·음수·지원 범위 초과는 오류로 처리한다.
- 1회 환산 비용 c = B/k. 내부 계산에서는 환산 단가를 반올림하거나 소수점을 버리지 않는다. 표시만 적절히 반올림하고 음식 수량은 최종 나눗셈 후 버린다.
- 기존 확률·횟수 공식은 그대로 사용하고 비용에는 c를 적용한다. 예: 1%, 10회 33,000원, 확정 천장 200회 → 최대 환산 비용 660,000원, 천장 미적용 99% 도달 459회 → 환산 비용 1,514,700원.
- 이는 사용자가 묶음 가격을 편하게 입력하기 위한 **횟수당 환산 모델**이다. 묶음 전체를 반드시 결제해야 하는 실제 구매 총액이나 미사용 횟수 비용은 포함하지 않는다. 다회차 결과는 ‘다회차 · 1회 환산 기준’, 금액은 ‘환산 비용’으로 표시해 실제 결제액으로 오해하지 않게 한다.
- 예를 들어 459회분의 환산 비용은 1,514,700원이지만 10회 묶음만 구매 가능하면 실제 46묶음 구매액은 1,518,000원이다. 묶음 결제 단위 올림 및 묶음 단위 중단의 평균 결제액 모델은 별도 확장 사항이다.

### 음식 환산 및 추후 가격 입력

- 가격 기준 연도는 **2025년**으로 준비한다. 실제 가격은 사용자가 추후 입력할 값이며, 확인되지 않은 값을 2025년 평균 통계로 표시하지 않는다.
- 음식별 단가, 단위, 기준 연도, 출처 또는 사용자 입력 여부를 계산 로직과 분리해서 저장한다. 가격 수정은 보조 시트에서 제공하여 계산 입력 화면에 음식 단가 입력칸을 추가하지 않는다.
- 기본 환산 금액은 **천장 적용 최대 비용**이며 사용한 금액을 제목 아래 명시한다. 확정 천장이 없으면 유한한 평균 예상 비용을 사용하고 ‘평균 예상 비용 기준’으로 표시한다. 평균도 계산 불가능하면 환산하지 않는다.
- 각 음식은 같은 금액으로 해당 음식만 구매하는 독립적인 비교다. 합산 식단이 아니다.
- 수량 = floor(환산 금액 ÷ 음식 단가). 반올림하지 않고 소수점을 버린다. 표시용으로 반올림한 평균 금액이 아니라 원래 계산값을 사용한다.
- 단가가 미입력·0·음수이면 나누지 않고 ‘가격 입력 예정’ 또는 입력 오류로 표시한다. 무료 뽑기 결과는 0개다.
- 아래는 시안 확인용 **임시 예시 단가**이며 실제 2025년 가격 자료가 아니다. 정식 기본값으로 확정하지 않는다.

| 음식 | 임시 예시 단가 | 600,000원 환산 |
|---|---:|---:|
| 치킨 | 25,000원 / 마리 | 24마리 |
| 족발 | 40,000원 / 접시 | 15접시 |
| 냉면 | 12,000원 / 그릇 | 50그릇 |
| 순대국밥 | 10,000원 / 그릇 | 60그릇 |
| 햄버거 | 6,000원 / 개 | 100개 |

소수점 버림 검증 예: 600,000원 ÷ 23,000원 = 26마리, 9,999원 ÷ 10,000원 = 0그릇.

## 3. 가장 중요한 계산 원칙

‘확률이 1%이므로 최대 100회에 반드시 획득’이라는 문구는 사용하지 않는다. 100회는 천장이 없을 때의 평균 횟수이며, 100회 안에 적어도 한 번 획득할 확률은 약 63.40%다. 99%도 100% 보장은 아니다.

입력 확률을 p=입력값/100, 1회 비용을 c, 확정 천장을 T로 정의한다. 천장은 반드시 목표 캐릭터를 T회째까지 확정 획득하는 조건이어야 한다. 단순히 최고 등급의 다른 캐릭터가 보장되는 천장은 목표 캐릭터 확정 천장으로 계산하면 안 된다.

### 천장 없음: 0<p<1

- n회 안에 적어도 한 번 획득할 확률: 1−(1−p)^n
- 평균 횟수: 1/p
- 평균 비용: c/p
- 누적 확률 99% 이상에 도달하는 최소 횟수: ceil(ln(0.01)/ln(1−p))
- 위 횟수만큼 시도하는 비용: 횟수 × c
- 확정 최대 횟수·최대 비용: 보장할 수 없음

### 목표 캐릭터 확정 천장 있음

- n<T에서는 위 독립시행 공식, n≥T에서는 누적 확률 100%.
- 확정 최대 횟수: T / 확정 최대 비용: T×c.
- 천장 적용 99% 이상 도달 최소 횟수: min(천장 미적용 99% 횟수, T).
- 천장 적용 평균 횟수: [1−(1−p)^T]/p.
- 천장 적용 평균 비용: 위 평균 횟수 × c.

천장 미적용 결과를 비교용으로 함께 표시할 경우 ‘천장 미적용 가정’이라고 명시한다. 실제로 200회 천장이 있는데 459회가 필요하다고 단독 안내해서는 안 된다.

### 입력 및 예외

- 확률: 0~100%, 소수 허용. 목표 캐릭터 자체의 확률 입력.
- 비용: 0 이상의 정수 원. 음수·문자·범위 초과 입력은 오류 안내.
- 천장: 없음 또는 1 이상의 정수. 빈칸과 0을 임의로 같은 의미로 처리하지 않는다.
- p=0, 천장 없음: 획득 불가능, 99% 도달 불가, 평균 계산 불가.
- p=0, 유효한 확정 천장 있음: T회 확정, 평균도 T회.
- p=1: 첫 1회 획득, 비용 c. 입력 천장이 커도 최대 횟수는 1회다.
- 매우 작은 확률 및 큰 비용에서 무한대·NaN·정수 넘침을 화면에 노출하지 않는다. 지원 입력 범위를 정하고 안내한다.
- 구현은 log1p/expm1 등 안정적인 수치 계산을 고려하고, 올림 결과의 전후 횟수를 검증한다.

### 검증 예시

| 입력/항목 | 올바른 결과 |
|---|---|
| 1%, 3,000원, 천장 없음: 평균 | 100회 / 300,000원 |
| 같은 입력: 100회 누적 확률 | 약 63.40% |
| 같은 입력: 99% 도달 | 459회 / 1,377,000원 |
| 같은 입력 + 목표 캐릭터 200회 확정 천장: 최대 | 200회 / 600,000원 |
| 같은 입력 + 확정 천장: 99% 이상 도달 | 200회 / 600,000원, 해당 시점에는 100% |
| 같은 입력 + 확정 천장: 평균 | 약 86.60회 / 약 259,806원 |

권장 문구: ‘입력한 조건에서 천장이 없다면 누적 획득 확률 99%에 도달하는 최소 시도 횟수는 459회이며, 이 횟수까지 시도하는 비용은 1,377,000원입니다. 획득을 보장하지 않습니다. 목표 캐릭터가 200회에 확정되는 천장을 적용하면 최대 600,000원입니다.’

## 4. 개발 방식과 완료 기준

Android 우선 출시이므로 Kotlin + Jetpack Compose를 제안한다. Compose는 Android 공식 권장 UI 도구다. 기존 프로젝트가 있다면 먼저 구조를 확인하고 재사용 여부를 판단한다. [Android 공식 안내](https://developer.android.com/compose)

개발 순서: 계산 함수와 검증 → 시작·1회 입력·다회차 입력·결과 4개 화면과 보조 시트 → 기록 저장·삭제 → 접근성 및 실제 기기 테스트 → 출시 자료.

완료 기준:

- 잘못된 입력에서 계산이 진행되지 않고 이유가 보인다.
- 4개 화면 이동·계산, 음식 선택 전환, 보조 시트 닫기, 기록 재사용·삭제가 정상 동작한다.
- 계산 예시와 0%·100%·천장 1회·무료 뽑기 등 경계 조건 검증을 통과한다.
- 앱 재실행 후 기록이 유지되고 전체 삭제가 가능하다.
- 비행기 모드, 작은 화면, 큰 글꼴, 화면 회전에서 사용할 수 있다.
- 불필요한 권한과 외부 전송 SDK가 없다. ‘외부 전송 없음’ 안내를 하려면 백업 설정과 포함 SDK도 확인한다.
- 설치 테스트용 APK, 출시용 서명 AAB, 실행 설명, 검증 결과를 준비한다. 서명 키와 비밀번호는 저장소에 넣지 않는다.

2026년 10월 13일 확인한 일반 모바일 신규 앱 기준은 target API 36 이상이다. 실제 제출일에 다시 확인한다. [대상 API 요구사항](https://developer.android.com/google/play/requirements/target-sdk) · [AAB 설명](https://developer.android.com/guide/app-bundle)

```text
Google Play에 출시할 한국어 Android 앱 ‘과금계산기’를 구현해줘.
첨부한 개발·출시 계획서를 기능 명세로, 예상 이미지를 디자인 참고로 사용해줘.

먼저 작업 폴더의 지침과 기존 프로젝트를 확인해줘. 기존 코드가 있다면 재사용 가능성을 판단하고, 새 Android 프로젝트가 필요하면 Kotlin + Jetpack Compose로 만들어줘.

첫 버전은 로그인, 서버, 광고, 인앱결제 없이 오프라인으로 동작하게 해줘.
시작·1회 입력·다회차 입력·공통 결과의 4종 화면을 만들어줘. 시작 화면에 1회 비용 계산, 다회차 비용 계산 버튼 두 개로 각 입력 화면을 열어줘. 하단 탭은 없애줘.
1회 입력 화면에 확률 %, 1회 비용 원, 천장 회 숫자 입력칸을 가로 한 줄로 배치해줘. 다회차 입력 화면은 확률·천장 한 줄, 묶음 횟수·묶음 가격 한 줄로 구성하고 10회에 33,000원을 쉽게 입력하게 해줘. B/k로 1회 단가를 환산하고 반올림 전 값으로 계산해줘. 다회차 결과에는 환산 비용임을 명시하고 실제 묶음 결제 총액과 구분해줘.
목표 캐릭터 확정 천장 체크박스를 끄면 천장 없이 계산하고 천장 칸은 비활성화해줘.
결과 보기를 누르면 결과 화면으로 이동하여 최대 비용, 평균 비용, 천장 미적용 99% 비용과 짧은 설명을 표시해줘.
다시 계산이나 뒤로가기를 누르면 입력값을 유지한 채 입력 화면으로 돌아가고, 결과 보기를 다시 누르면 수정한 값으로 재계산해줘.
기록 저장·재사용·삭제, 도움말과 상세 계산은 보조 시트나 펼치기로 제공해줘.
결과 화면의 음식 선택은 버튼 하나로 만들어줘. 치킨 ↻ 버튼을 누를 때마다 치킨→족발→냉면→순대국밥→햄버거→치킨 순서로 순환하고 현재 순번을 1/5처럼 표시해줘. 선택 음식 하나의 사진·이름·수량·단가만 보여주고 동시에 갱신해줘.
2025년 기준 음식 가격은 추후 입력하도록 데이터와 화면을 분리하고, 미입력 단가는 가격 입력 예정으로 표시해줘.
시안의 음식 가격은 임시 예시이며 실제 2025년 통계나 정식 기본값으로 사용하지 마.
환산 금액은 천장 적용 최대 비용, 천장 없을 때는 유한한 평균 비용이며 어떤 금액인지 표시해줘.
각 음식 수량은 floor(환산 금액/단가)로 소수점을 버리고, 단가 0·음수·미입력은 계산하지 마.

확률은 매회 일정하고 첫 획득 시 중단하며 천장 진행도 0회부터 시작한다고 명시해줘.
천장 미적용 누적 확률은 1-(1-p)^n, 평균은 1/p, 99% 도달 횟수는 ceil(log(0.01)/log(1-p))야.
확정 천장 T가 있으면 누적 확률은 T회부터 100%, 최대 횟수는 T, 99% 도달 횟수는 min(n99,T), 평균 횟수는 [1-(1-p)^T]/p야.
0%, 100%, 천장 1회, 비용 0원, 소수 확률, 매우 작은 확률, 큰 비용을 별도로 처리해줘.
100% 확률이면 천장보다 먼저 1회로 끝나는 것이 맞아.
‘평균’이나 ‘99%’를 ‘반드시 획득하는 최대 횟수’로 표현하지 마.
최고 등급만 보장하고 목표 캐릭터를 보장하지 않는 천장은 이 버전에서 지원하지 않는다고 안내해줘.

1%, 3,000원, 천장 없음에서 n99=459회, 비용=1,377,000원,
목표 캐릭터 200회 확정 천장에서는 최대 200회·600,000원인지 테스트해줘.
계산 함수 테스트와 핵심 화면 흐름 검증을 수행하고 실제 실행하지 못한 검증은 명시해줘.

흰 배경·짙은 회색 글자와 버튼을 사용하고 파란 결과 카드나 장식은 없애줘. 또한 작은 화면, 큰 글꼴, 뒤로가기, 화면 회전을 지원해줘.
계산 로직과 화면 코드는 분리해줘. 불필요한 권한을 요청하지 마.
단계별로 구현하고 가능한 빌드·테스트를 실행하여 실패를 수정해줘.
실행 가능한 소스, 설치 테스트용 APK, 출시용 AAB 빌드 절차, README, 검증 결과를 남겨줘.
정책 문서와 스토어 등록 문구는 실제 구현과 일치하는 초안으로 작성해줘.
사업자번호·연락처·서명 비밀번호를 임의로 만들거나 저장소에 넣지 마.
본인 인증, 실제 등록비 결제, 사업자 신청, 스토어 최종 제출은 내가 직접 진행할 수 있게 안내해줘.
```

## 6. 사업자등록 및 수익화 준비

앱 공개, 한국 사업자등록, Google Play 개발자 계정은 서로 다른 절차다. 무료·무수익 앱을 만드는 것만으로 모든 경우에 사업자등록이 필수라고 단정할 수는 없다. 광고·유료 판매 등 지속적인 사업을 계획한다면 수익화 전에 사업자등록을 준비하는 일정으로 잡는다.

### 사업자등록 순서

1. 상호, 대표자, 사업장 주소, 개업일, 실제 수익 모델을 정한다.
2. 신분 확인 자료, 사업자등록 신청서, 임차 사업장인 경우 임대차계약서 등 해당 구비서류를 준비한다.
3. 홈택스 또는 세무서에서 개인사업자 등록을 신청한다. 국세청 안내상 사업 개시 전 또는 시작일부터 20일 이내 신청한다. [국세청 사업자등록 안내](https://s.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7777&mi=2444)
4. 업종은 앱 개발·공급 등 실제 사업 내용을 설명해 정한다. 업종코드 및 일반/간이 과세유형은 매출 계획과 거래 형태를 바탕으로 세무서에 확인하며, 코드 하나를 임의로 확정하지 않는다.
5. 사업자등록증 발급 후 개발자 계정·결제 프로필에 사용하는 이름과 주소를 일치시킨다. 정산 계좌와 매출·비용 증빙 보관 방식을 준비한다.

### 수익 모델에 따른 차이

| 모델 | 준비 사항 |
|---|---|
| 무료·광고 없음 | 첫 출시 권장안. 개발자 계정·검증·개인정보처리방침·스토어 심사 준비 |
| 무료·광고 포함 | 사업자·세무 처리 검토, 광고 SDK의 데이터 수집과 광고 포함 여부 신고 반영 |
| 유료 앱·인앱결제 | 사업자등록 및 통신판매 관련 정보, 결제·정산·세금·환불·현재 결제 정책 준비 |

한국 소재 개발자가 유료 앱이나 인앱결제 앱을 배포할 때 Google은 사업자등록번호, 통신판매업 신고번호, 신고기관명을 요구한다. 한국 개인 개발자는 공개되는 개발자 전화번호 인증도 필요하다. [Google 한국 배포 요건](https://support.google.com/googleplay/android-developer/answer/6223646?hl=ko)

통신판매업 신고는 사업자등록과 별개다. 유료화 전 정부24 또는 관할 지자체 절차를 확인한다. 신고 면제 여부와 Google의 정보 제출 요구는 따로 확인해야 한다. 정부24 민원 수수료 안내와 별도로 등록면허세 등 실제 부담 여부는 관할 지자체에 확인한다. [정부24 통신판매업 신고](https://www.gov.kr/mw/AA020InfoCappView.do?CappBizCD=11300000006&HighCtgCD=A09006)

한국 소재 개발자의 한국 고객 대상 디지털 콘텐츠 판매에 대한 부가세 책임도 확인한다. 스토어가 모든 세무 처리를 대신한다고 가정하지 않는다. [Google 세금 안내](https://support.google.com/googleplay/android-developer/answer/138000?hl=ko)

## 7. Google Play 출시 절차

1. **계정 유형 결정:** 개인으로 운영할지 조직을 대표할지 실제 운영 주체에 맞게 선택한다. 사업자등록과 계정 유형은 별개이므로 ‘개인사업자이면 자동으로 조직 계정’이라고 가정하지 않는다. 조직 계정은 일반적으로 D-U-N-S 번호, 조직 자료, 웹사이트와 연락처를 요구하므로 미리 준비한다. D-U-N-S 무료 신청 경로가 있다. [계정 준비 정보](https://support.google.com/googleplay/android-developer/answer/13628312?hl=ko)
2. **등록·인증:** Play Console 등록비는 일회성 US$25다. 본인·연락처 및 필요한 기기 인증을 완료한다. [Play Console 시작하기](https://support.google.com/googleplay/android-developer/answer/6112435?hl=ko)
3. **앱 생성:** 이름, 기본 언어, 앱 유형, 무료/유료, 배포 국가를 정한다. 패키지명과 서명 키 관리 방식을 확정하고 AAB를 준비한다.
4. **스토어 자료:** 앱 아이콘, 실제 앱 스크린샷, 그래픽, 간단·상세 설명, 문의 이메일, 공개 개인정보처리방침 URL을 준비한다. 이 계획서의 생성 이미지는 디자인 참고용이며 실제 제품 스크린샷으로 대체한다.
5. **앱 콘텐츠 신고:** 데이터 보안, 광고 여부, 콘텐츠 등급, 대상 연령, 앱 접근 권한 등을 실제 구현대로 작성한다. 데이터를 수집하지 않아도 데이터 보안 양식과 개인정보처리방침 링크가 필요하다. [데이터 보안 안내](https://support.google.com/googleplay/android-developer/answer/10787469?hl=ko)
6. **내부 테스트:** 직접 설치하여 계산·입력·화면 이동·오프라인·기록 삭제·앱 재실행을 확인한다. 사전 출시 보고서의 충돌과 문제를 수정한다.
7. **필요한 비공개 테스트:** 2023년 11월 13일 이후 생성한 개인 계정은 최소 12명이 연속 14일 이상 참여하는 비공개 테스트가 필요하다. 이후 프로덕션 액세스를 신청하며 자동 승인되는 것은 아니다. 실제 사용 피드백과 개선 내용을 기록한다. [개인 계정 테스트 요건](https://support.google.com/googleplay/android-developer/answer/14151465?hl=ko)
8. **정식 출시 신청:** 권한 승인 후 최종 출시 자료와 AAB를 제출하고 심사에 대응한다. 계정 대시보드의 개발자·앱 검증 상태도 확인한다.
9. **출시 이후:** 충돌, 리뷰, 문의, 계산 오류를 점검하고 개선 버전을 배포한다. 정책과 대상 API 변경을 주기적으로 확인한다.

## 8. 일정과 비용

아래는 1인 개발을 위한 계획 추정이며 출시일 보장이 아니다. 인증·심사·D-U-N-S 발급 기간에 따라 연장된다.

| 기간 | 작업 | 완료 산출물 |
|---|---|---|
| 1주차 | 앱 범위·천장 조건·디자인 확정, 계정 및 사업자 준비 시작 | 확정 명세·화면 시안 |
| 2~3주차 | 계산 로직, 4개 화면, 기록·음식 선택 및 환산 기능 | 설치 가능한 테스트 앱 |
| 4주차 | 실제 기기 검증, 정책 문서, 스토어 자료 | 비공개 테스트 제출본 |
| 5~6주차 | 해당 계정의 14일 비공개 테스트, 피드백 수정 | 테스트 이력·프로덕션 액세스 신청 |
| 7주차 이후 | 정식 제출·심사 대응·출시 | Google Play 공개 |

- Play Console: US$25 일회성. 원화 청구액은 결제일 환율·카드 수수료에 따라 달라진다.
- 개발 비용: 본인 작업 시간, 사용하는 Codex 요금제 등 별도. 외주 비용은 범위 확정 후 견적이 필요하다.
- 서버: 제안한 오프라인 범위에는 별도 앱 서버가 필요하지 않다.
- 정책 문서 호스팅: 공개 URL 필요. 무료 호스팅 사용 가능 여부를 확인한다. 개인 도메인은 선택 사항이다.
- 행정·세무: 통신판매 관련 지방세, 주소 준비, 세무 대행 등을 선택 사항과 의무 사항으로 나누어 실제 조건에 맞게 확인한다.
- 조직 인증·사업자 준비는 개발과 병행한다. 결제나 광고는 첫 출시 후 별도 일정으로 잡는다.

- [ ] 목표 캐릭터의 확률과 천장 조건이 명확하다.
- [ ] 99%와 평균을 보장으로 표현하지 않는다.
- [ ] 4개 화면 이동·입력·계산, 기록 삭제, 음식 단일 선택과 사진 전환, 환산의 소수점 버림이 정상 동작한다.
- [ ] 사업자·통신판매·계정 정보가 수익 모델에 맞게 준비되었다.
- [ ] 이름·주소·연락처 및 조직 정보가 검증 자료와 일치한다.
- [ ] 개인정보처리방침 및 데이터 보안 신고가 실제 앱과 일치한다.
- [ ] 서명 키를 안전하게 보관하고 출시 파일을 검증했다.
- [ ] 필요한 테스트와 프로덕션 액세스 승인을 완료했다.
- [ ] 실제 앱 스크린샷과 설명을 등록했다.
- [ ] 개발자 본인이 최종 스토어 제출 내용을 확인했다.

## 10. 시안 기록

최신 예상 이미지: `app-screen-concept-v4.png`. 기본 내장 이미지 생성 도구로 제작했고 생성 요청문은 `image-generation-prompt-v4.txt`에 보관한다. 과금계산기 이름, 시작 화면 두 버튼, 1회·다회차 입력 화면, 음식 순환 버튼 하나를 반영했다. 결과 화면은 1회 비용 3,000원에 대한 600,000원 예시이며 다회차 33,000원 입력의 결과가 아니다.

시안의 음식 단가는 임시 예시이며 실제 2025년 통계가 아니다. `food-prices.json`은 가격 미입력(null) 상태다. 이전 시안과 생성 요청문은 이력으로 보관한다. 현재 산출물은 기획서와 이미지이며 실행 가능한 앱은 아직 구현하지 않았다.
